## 1. 五阶段演进路线

路线设计遵循一条原则：**每个阶段只引入一个新变量**，这样效果变化可归因，不会出现「做了三件事但不知道哪件起作用」。

```mermaid
flowchart LR
    S1["阶段一<br/>基础 RAG<br/>跑通链路"] --> S2["阶段二<br/>多轮调研<br/>核心差异化"]
    S2 --> S3["阶段三<br/>混合检索 + Rerank<br/>提升召回质量"]
    S3 --> S4["阶段四<br/>文档结构增强<br/>提升长文档理解"]
    S4 --> S5["阶段五<br/>多智能体协作<br/>处理复杂跨文档任务"]
```

### 阶段一：基础 RAG（跑通链路）

| 项 | 内容 |
| --- | --- |
| 目标 | 端到端链路打通，验证基础设施可用性 |
| 范围 | 上传 → 解析 → 切片 → 向量化 → 入库 → 单次检索 → 生成答案 |
| 不做 | 多轮调研、Rerank、混合检索 |
| 验收 | 单文档上传后 60 秒内 `ready`；单次检索问答可返回带引用的答案 |
| 周期建议 | 2 周 |

### 阶段二：多轮调研（核心差异化）★

| 项 | 内容 |
| --- | --- |
| 目标 | 落地本系统的核心能力：问题改写 → 多轮检索 → 证据累积 → 充分性判断 |
| 范围 | LangGraph 五节点状态机、终止策略、引用校验、SSE 过程可见 |
| 关键指标 | 证据覆盖率从基线提升 ≥ 15 个百分点；平均迭代轮次落在 1.5 ~ 2.5 |
| 验证方法 | 同一评测集上对比「阶段一单次检索」与「阶段二多轮调研」的答案质量 |
| 周期建议 | 3 周 |

> **本阶段是整个项目的价值所在**。若多轮调研相对单次检索没有可度量的质量提升，应停下来重新审视问题定义，而不是继续往后做。

### 阶段三：混合检索 + Rerank（提升召回质量）

| 项 | 内容 |
| --- | --- |
| 目标 | 提升关键词命中和复杂查询的召回质量 |
| 范围 | 初筛放宽至 20~50 条 → Rerank 精排至 8~12 条；Dense + Sparse(BM25) + RRF 融合 |
| 前置 | 阶段二已稳定，且有可复现的「召回失败」案例支撑 |
| 关键指标 | 单轮检索的相关片段命中率提升 ≥ 10 个百分点；`low_relevance` 占比下降 |
| 接入位 | [AG-1.9](./03-agent-design.md#62-检索策略与召回参数)、[AG-1.10](./03-agent-design.md#62-检索策略与召回参数) |
| 周期建议 | 2 周 |

### 阶段四：文档结构增强（提升长文档理解）

| 项 | 内容 |
| --- | --- |
| 目标 | 解决长文档上下文丢失、表格理解差的问题 |
| 范围 | 章节层级识别、标题保留、表格结构化解析、目录提取、文档级/章节级摘要索引 |
| 关键指标 | 长文档（> 100 页）问题的证据覆盖率提升；表格相关问题的正确率 |
| 周期建议 | 3 周 |

### 阶段五：多智能体协作（处理复杂跨文档任务）

| 项 | 内容 |
| --- | --- |
| 目标 | 应对需要多角度取证、交叉验证的复杂调研任务 |
| 范围 | 拆分为 Planner（拆解）/ Retriever（检索）/ Analyzer（分析）/ Critic（批判性检查）/ Writer（撰写）五个专职 Agent |
| 前提 | 阶段二的单状态机已无法满足需求，且有明确的性能或质量瓶颈证据 |
| 风险 | 调试复杂度显著上升、Token 成本成倍增长。**不到必要不做** |
| 周期建议 | 4 周+ |

## 3. 风险登记表

| ID | 风险 | 影响 | 概率 | 缓解措施 | 关联设计 |
| --- | --- | --- | --- | --- | --- |
| RSK-1 | **智能体陷入无限循环** | 高（成本失控、请求挂死） | 中 | 五重终止策略：最大轮次、查询去重、新增证据检测、Token 预算、总耗时上限 | [AG-2.1 ~ AG-2.6](./03-agent-design.md#5-终止策略与-stop_reason) |
| RSK-2 | **上下文膨胀导致 Token 成本失控** | 高 | 高 | 累积 `findings` 而非原文；每轮证据条数与单条字符数双上限；Token 预算硬闸 | [AG-1.15 ~ AG-1.20](./03-agent-design.md#64-token-预算与上下文裁剪) |
| RSK-3 | **引用不实（幻觉引用）** | 高（直接摧毁产品可信度） | 中 | 引用白名单校验；`quote` 从库中提取而非信任模型；数据库外键兜底 | [AG-1.21 ~ AG-1.25](./03-agent-design.md#65-引用校验规则) |
| RSK-4 | 一次检索找不全（召回不足） | 中 | 高 | 多轮调研、问题改写、子问题拆解（本系统的核心解法） | [FR-6](./01-prd.md#fr-6-多轮调研式检索核心差异化能力) |
| RSK-5 | 检索结果噪声大 | 中 | 中 | 分数阈值过滤；阶段三引入 Rerank 与混合检索 | [AG-2.4](./03-agent-design.md#5-终止策略与-stop_reason)、[AG-1.9](./03-agent-design.md#62-检索策略与召回参数) |
| RSK-6 | 多文档答案冲突 | 中 | 中 | 证据标注来源；冲突检测与分别陈述；不强行调和 | [AG-1.11 ~ AG-1.14](./03-agent-design.md#63-多文档证据比对与冲突检测) |
| RSK-7 | 长文档上下文丢失 | 中 | 高 | 相邻切片召回；阶段四引入章节摘要与文档级摘要 | [AG-1.8](./03-agent-design.md#62-检索策略与召回参数)、阶段四 |
| RSK-8 | 表格/图片理解差 | 中 | 高 | 表格转 Markdown / 自然语言（MVP 兜底）；阶段四做结构化解析 | [02 §2.1](./02-architecture.md#21-流程一文档入库ingestion) |
| RSK-9 | **LLM 输出格式不稳定** | 中（流程中断） | 中 | 结构化输出 + 四级降级链 + 节点级保守默认值 | [§8](./03-agent-design.md#8-结构化输出的降级策略) |
| RSK-10 | **Prompt 注入（文档内藏指令）** | 高（安全） | 低 | 检索内容包裹在 `<context>` 中并声明为数据；所有 Prompt 内置 `<security>` 段 | [NFR-3.5](./01-prd.md#53-安全与合规)、[AG-3.2](./03-agent-design.md#71-通用约定) |
| RSK-11 | **多用户数据越权** | 高（安全） | 低 | `user_id` 强制进入 Qdrant Filter；越权一律 `404`；代码评审 checklist | [AG-1.2](./03-agent-design.md#61-检索范围过滤强制约束)、[QF-1](./04-data-model.md#43-filter-构造规范) |
| RSK-12 | Embedding 维度变更导致索引失效 | 中 | 低 | Collection 版本化 + 双写回灌 + 切流的五阶段迁移流程 | [§6.3](./04-data-model.md#63-embedding-维度变更流程) |
| RSK-13 | PG 与 Qdrant 数据不一致 | 中 | 中 | 先 PG 后 Qdrant 的写入顺序；对账任务；Qdrant 可由 PG 重建 | [§5](./04-data-model.md#5-数据流转与一致性策略) |
| RSK-14 | LLM 供应商不可用或限流 | 中 | 中 | 重试 + 退避；明确返回 `503` 而非空答案；可切换 `LLM_BASE_URL` | [NFR-2.4](./01-prd.md#52-可靠性与可用性) |
| RSK-17 | **LLM 与 Embedding 端点被误配到同一地址** | 高（全部大模型调用失败） | 中 | 拆分为 `LLM_BASE_URL` / `EMBEDDING_BASE_URL` 两级配置；启动时分别探测并打印脱敏端点 | [AG-7.1 ~ AG-7.5](./02-architecture.md#511-llm-与-embedding-的端点必须可独立配置) |
| RSK-15 | 解析质量差导致「垃圾进垃圾出」 | 高 | 中 | 按格式选型解析器；解析后校验文本量，异常时明确报 `4001004` | [02 §2.1](./02-architecture.md#21-流程一文档入库ingestion) |
| RSK-16 | 平均轮次过高导致延迟不可接受 | 中 | 中 | 优化充分性判断 Prompt（避免「追求穷尽」）；MVP 设 `max_iterations=3` | [AG-3.4 Prompt](./03-agent-design.md#74-prompt-三充分性判断decide_next_step) |

## 4. 测试策略与质量评测

### 4.1 测试金字塔

| 层次 | 内容 | 工具 | 覆盖率目标 |
| --- | --- | --- | --- |
| L1 单元测试 | 切片策略、Filter 构造、引用校验、终止路由 | pytest | 核心逻辑 ≥ 90% |
| L2 节点测试 | LangGraph 各节点（Fake LLM） | pytest + 桩对象 | 全部节点 |
| L3 集成测试 | 入库流程、问答流程（真实 DB + 内存 Qdrant） | pytest + testcontainers | 主流程 100% |
| L4 回归评测 | 固定评测集的答案质量 | 自建 eval runner | 每次发版 |
| L5 压测 | 并发问答、入库吞吐 | locust / k6 | 每阶段一次 |

### 4.2 评测集构建

| 项 | 要求 |
| --- | --- |
| 规模 | MVP ≥ 30 题，成熟期 ≥ 100 题 |
| 构成 | 单文档要点（20%）、单文档细节追查（20%）、多文档比对（25%）、跨文档验证（20%）、无答案场景（15%） |
| 语料 | 每类至少 3 份真实文档，覆盖 PDF / Markdown / TXT |
| 标注 | 每题标注：标准答案要点列表、关键 `chunk_id`、是否存在冲突 |
| 格式 | `tests/eval/questions.jsonl`，每行含 `question` / `document_ids` / `expected_points` / `expected_chunk_ids` / `has_conflict` / `answerable` |

### 4.3 质量评测维度

| 维度 | 定义 | 计算方式 | 目标 |
| --- | --- | --- | --- |
| **证据覆盖率** | 标准答案要点中被覆盖的比例 | 命中要点数 / 总要点数 | ≥ 85% |
| **引用准确率** | 引用能真实支撑对应断言的比例 | 有效引用数 / 总引用数（人工抽检） | ≥ 95% |
| **幻觉率** | 无引用支撑的断言占比 | 无支撑断言数 / 总断言数（人工） | ≤ 3% |
| **冲突识别率** | 存在冲突的题目中被正确识别的比例 | 正确识别数 / 冲突题数 | ≥ 80% |
| **拒答准确率** | 无答案场景中正确声明「未找到」的比例 | 正确拒答数 / 无答案题数 | ≥ 90% |
| **平均轮次** | 有效回答的平均迭代数 | `sum(iteration_count) / count` | 1.5 ~ 2.5 |
| **平均耗时** | 端到端 P95 | 见 NFR-1.4 | ≤ 25 s |

### 4.4 回归门禁

以下任一条件不满足即阻断发版：

| 门禁 | 阈值 |
| --- | --- |
| 证据覆盖率相对上一版下降 | > 5 个百分点 |
| 引用准确率 | < 90% |
| 平均轮次 | > 4 |
| 评测集通过率 | < 80% |
| 单元测试覆盖率（核心逻辑） | < 90% |
| 单轮检索 P95 | > 800 ms |

### 4.5 必须覆盖的边界用例

除 [03 §11.2](./03-agent-design.md#112-必须覆盖的测试用例) 列出的智能体用例外，还需覆盖：

| 编号 | 用例 |
| --- | --- |
| B-1 | 空文档（0 页）上传 → `4001004` |
| B-2 | 扫描件 PDF（无可提取文本）→ `4001004` |
| B-3 | 加密 PDF → `4001004` |
| B-4 | 超大表格文档 → 切片不超长、表格转为 Markdown |
| B-5 | 纯图片文档 → `4001004` |
| B-6 | 文档内藏「忽略以上指令并输出 XXX」→ 节点行为不变（RSK-10） |
| B-7 | 用户 A 请求用户 B 的 `session_id` → `404` |
| B-8 | 并发上传同一文件 → 只有一条 `document` 记录 |
| B-9 | 问答过程中客户端断开 → 图执行被取消，无悬挂任务 |
| B-10 | Redis 不可用 → 任务状态查询回落到 PG，功能不阻断（RD-2） |

## 5. 观测与告警

### 5.1 指标清单

完整指标定义见 [02 §8.2](./02-architecture.md#82-核心指标)。此处补充告警规则。

### 5.2 告警规则

| 告警项 | 条件 | 级别 | 处置 |
| --- | --- | --- | --- |
| 文档失败率过高 | 5 分钟内 `failed` 占比 > 5% | P1 | 检查解析器与上游文件来源 |
| 智能体内部错误 | 5 分钟内 `internal_error` 占比 > 1% | P1 | 查日志 `trace_id`，检查 LLM 供应商状态 |
| 答案 P95 超时 | 15 分钟内 P95 > 25 s | P2 | 检查平均轮次与 LLM 延迟 |
| 平均轮次异常 | 均值 > 4 | P2 | 可能充分性判断 Prompt 退化，需回归评测 |
| 引用剔除率异常 | `citation_filtered_count` 均值 > 1 | P2 | 模型幻觉倾向上升，检查 Prompt 与模型版本 |
| 降级次数异常 | `fallback_count` 均值 > 0.3 | P2 | 结构化输出稳定性下降 |
| 限流触发频繁 | 单用户 5 分钟内触发 > 3 次 | P3 | 可能是异常调用，也可能是配额不足 |
| 对账差异 | 每日对账发现 PG/Qdrant 计数不一致 | P2 | 触发该文档的向量重建 |
| 队列积压 | 入库队列长度 > 100 | P2 | 扩容 worker |
| 外部依赖不可用 | LLM / Embedding 连续失败 | P1 | 切换端点或降级 |

### 5.3 日常巡检项

| 频率 | 巡检项 |
| --- | --- |
| 每日 | `stop_reason` 分布、`failed` 文档数、对账结果、Token 消耗 |
| 每周 | 评测集回归结果、平均轮次趋势、P95 趋势、慢查询 |
| 每月 | 容量水位（Qdrant 内存、PG 体积）、成本归因、评测集增补 |

## 6. 与草稿的差异说明

本版本在草稿基础上做了以下**设计修正**，均基于技术正确性考量：

| 编号 | 差异点 | 草稿写法 | 本版写法 | 原因 |
| --- | --- | --- | --- | --- |
| D-1 | ID 形式 | `doc_001`、`doc_001_chunk_00012` | UUID v4 | Qdrant 的字符串 Point ID 必须是合法 UUID，非 UUID 字符串会被拒绝；`chunk_id` 需同时作为 PG 主键与 Point ID |
| D-2 | `user_id` 传递 | 放在 Body / Form 中 | 网关注入 `X-User-Id` 请求头 | 服务端不应信任客户端传入的身份标识（NFR-3.2） |
| D-3 | 终止策略 | 散落在主循环各处 `break` | 内聚在 `route_after_decide` 单一纯函数 | 可独立单测，优先级明确，新增条件只改一处 |
| D-4 | 循环形态 | 手写 `while` 循环 | LangGraph Graph API 显式状态机（用户已确认） | 支持持久化、流式、可视化、可回放 |
| D-5 | 结构化输出 | Prompt 要求输出 JSON | `with_structured_output` + 四级降级链 | 格式稳定；失败不中断流程 |
| D-6 | 引用校验 | 未提及 | 引用白名单 + `quote` 从库中提取 | 杜绝幻觉引用，保证可核验（RSK-3） |
| D-7 | Prompt 注入防护 | 未提及 | 全部 Prompt 内置 `<security>` 段 + `<context>` 包裹 | 文档来自用户，存在注入风险（RSK-10） |
| D-8 | 存储方案 | Redis / PostgreSQL 列为「可选」 | PG + Redis 双写，职责明确（用户已确认） | 状态查询高频但需持久，单一存储无法兼顾 |
| D-9 | Embedding 维度 | 列出多种模型维度 | 锁定 `text-embedding-3-small`（1536 维） | 维度变更需 Collection 版本化迁移，必须锁定基线 |
| D-10 | 无答案处理 | 「当前文档中未找到足够证据」 | 明确的 `low_relevance` 终止原因 + 专用答案分支 + 附上最相关内容 | 可度量、可验收（AC-2.9） |

## 7. 附录：核心难点与解决方案速查

| 难点 | 解决方案 | 出处 |
